# 坤坤食帖 · UI 评审与优化方案（v4）

> 评审对象：`KunKun-CaiDan`（原生微信小程序，12 页 / 11 个 utils / 1 个云函数，约 1.0 万行）
> 评审方法：全量代码阅读 + 设计令牌量化统计（字号/圆角/时长/缓动熵）+ WCAG 对比度计算 + 预览稿放大目视
> 评审日期：2026-10-23

---

## 一、结论摘要

**这套 UI 的问题不是"不好看"，而是"审美已经领先于系统"。**

视觉命题（国潮食帖：宣纸、墨线、朱砂印、小票、竖排题签）成立且有辨识度，明显脱离了通用卡片流。
真正的短板集中在三处：

1. **系统熵过高**——21 种动画时长、11 种圆角、19 种字号、5 条缓动曲线并存，导致同一产品在不同页面"手感不一致"。
2. **可读性与合规缺口**——纸色主题的辅助文字对比度只有 **3.90:1**，低于 WCAG AA 的 4.5:1；多个可点区域仅 18–36px，低于 44px 触控标准。
3. **动效有"意图"但缺"编排"**——单个动画都在讲道理，放在一起却互相抢戏：入场动画与按压反馈争用 `transform`、品类胶囊用 `padding` 过渡触发布局重排、主题扫过 1.26s 期间页面仍可点击。

**建议路径：不换风格，换系统。** 保留色相与版式语言，重建"令牌层 → 组件层 → 页面层"的三级秩序，把动效从"逐处调参"改为"按时序编排"。

### 评分（10 分制）

| 维度 | 现状 | 目标 | 主要缺口 |
|---|---|---|---|
| 品牌识别度 | 8.5 | 9.0 | 已成型，需克制印章滥用 |
| 配色系统 | 6.0 | 8.5 | 明度阶梯不足、辅助色不达标 |
| 排版层级 | 6.5 | 8.5 | 19 档字号、竖排小字可读性差 |
| 动效连贯性 | 6.0 | 8.5 | 令牌离散、属性违规、时序冲突 |
| 组件一致性 | 6.0 | 9.0 | 圆角/间距/卡片形态各自为政 |
| 无障碍 | 5.0 | 8.5 | 对比度、触控目标、语义标签 |
| 工程可维护性 | 6.5 | 8.5 | 样式未分层、组件未抽取 |
| 首屏效率 | 7.0 | 8.5 | 首屏 55% 无商品、串行云请求 |

## 二、应当保留的部分（重构中禁止破坏）

1. **设计命题清晰**。书眉（`.bookband`）+ 印章（`.seal`）+ 小票（`.slip`）+ 装裱双线（`.frame`）构成可复用的视觉签名，不是贴图式国潮。
2. **双主题 + 局域纸色作用域**。`.page--board`（灶房常暗）与 `.paper-scope`（暗底上的白纸单）解决了"深色工作台 + 亮色订单票据"的共存难题，这个结构值得保留并文档化。
3. **动效有因果**。"想吃"粒子飞向点菜单，交代了"东西去哪了"；主题切换从触点/对角铺开，交代了"变化从哪来"。这是很多成熟产品都没做到的。
4. **降级意识**。`reduce-motion` 已在 CSS 与 JS 双侧落地；触觉反馈统一封装且静默失败。
5. **数据层与视图层分离**。`utils/db.js` 统一错误提示、竞态令牌、倒排索引搜索、字段投影，页面只做编排。

## 三、问题清单（按严重度分级）

### P0 · 阻断体验或合规

| 编号 | 问题 | 证据 | 影响 |
|---|---|---|---|
| P0-1 | 纸色主题辅助文字对比度不足 | `styles/theme.wxss:24` `--ink-3: #7C7060`，在 `#EFE6D3` 上实测 **3.90:1**；`app.wxss:179` `.caption` 以 22rpx 使用该色，全项目 22rpx 出现 36 处 | 时间戳、描述、占位文字在户外/低亮度屏几乎不可读；不满足 WCAG AA |
| P0-2 | 布局属性参与过渡 | `pages/list/list.wxss:365` `.cat` 过渡 `padding-left/right 300ms` | 每次切换品类触发布局重排，与项目自定的"只动 transform/opacity"直接矛盾，中低端机掉帧 |
| P0-3 | 触控目标低于 44px | `.want` 72rpx≈36px、`.search__clear` 36rpx≈18px、`.seal--sm` 40rpx≈20px | 误触与点不中，拇指操作区尤其明显 |
| P0-4 | 底部三层控件互相遮挡 | `list.wxss`：tab 栏 104rpx+bottom 16；`.cart` bottom 140rpx、z-index 95；`.fab` bottom 170/276rpx、z-index 90 | 购物袋出现时 FAB 被压在其下；三层叠压占据约 260rpx 视口，内容被切 |
| P0-5 | 主题扫过期间页面仍可交互 | `theme-reveal/index.wxss:11` `pointer-events: none`，`index.js` 总时长 1270ms | 扫过中点击会命中底层卡片，可能误进详情；`_busy` 只锁组件自身，不锁页面 |

### P1 · 显著影响观感与一致性

| 编号 | 问题 | 证据 | 影响 |
|---|---|---|---|
| P1-1 | 令牌熵过高 | 21 种时长（100/120/160/180/200/220/240/250/260/280/300/320/360/420/440/460/520/600/750/760/1000ms）、11 种圆角、19 种字号、5 条缓动 | 页面之间"手感"不一致，改一处不知会波及哪里 |

| P1-3 | 入场动画与按压反馈争用 `transform` | `list.wxml:146` `.dish-card.enter` + `list.wxss:419` hover `transform: scale(.98)` | 卡片入场 460ms 内按压无反馈，手感"发木" |

| P1-6 | 卡片标题高度与截断规则冲突 | `.dish-card__name` `min-height: 78rpx` 同时用 `.clamp2` | 单行菜名下方留白 39rpx，双列网格高度参差 |
| P1-7 | 导航形态不统一 | 首页自定义导航（沉浸式书眉），二级页原生导航（居中标题） | 进出详情时标题样式与状态栏配色跳变，暗色主题下尤其明显 |
| P1-8 | 开关语义依赖位置 | `my.wxml:58-72` "日/月""开/关"双段按钮 | 状态靠左右位置推断，缺少明确的选中语义 |
| P1-9 | 印章通胀 | 每张菜卡、每条评论、每个统计项都挂 `.seal` | 强调色与印章本应是"稀缺信号"，现在变成背景噪声 |
| P1-10 | 文案门槛 | "食帖/落单/掌勺/灶火/寻味" | 首访用户需解码，空态缺少可执行动作 |

### P2 · 工程与细节

- **样式未分层**：`app.wxss` 664 行混合令牌、排版、组件、动效四类职责，页面无法只依赖其中一层。
- **组件未抽取**：`dish-card`、`ledger-row`、`empty`、底部操作栏在多个页面重复实现，改一处要改 N 处。
- **`setData` 抖动**：`list.js:210` 先 `setData({list:[], page:1})` 再请求，搜索时列表会闪空一次。
- **`onShow` 串行请求**：`list.js:86-98` 依次刷新身份、分类、轮播，三次云调用串行；建议 `Promise.all` + 5s 缓存。
- **图片无裁剪参数**：云存储 fileID 直出原图，首屏双列卡片各 300rpx 高，流量与解码成本偏高。
- **无视觉回归基线**：`preview/` 只有静态稿，没有截图 diff 机制，重构无法证明"没改坏"。

## 四、对标与取舍

| 参考体系 | 采纳什么 | 不采纳什么 |
|---|---|---|
| **Apple HIG**（Clarity / Deference / Depth） | 44pt 触控下限；内容优先于装饰；层级用排版而非阴影 | 不做大面积毛玻璃，不做过度留白（信息密度不适合点餐场景） |
| **Material 3 Motion** | "时长按语义分档"（micro / short / medium / long）而非按像素；强调型减速曲线 | 不照搬容器变换（container transform），小程序跨页共享元素成本过高 |
| **GitHub Primer（design tokens）** | 三层令牌：base（原始值）→ semantic（角色）→ component（组件别名） | 不引入其完整色板，色相必须服从"宣纸/朱砂" |
| **Radix Colors** | 按"用途"而非"深浅"命名（surface / text / border / solid），保证暗色模式可预测 | 不采用其 12 阶复杂度，本产品 4 阶足够 |
| **shadcn/ui** | 组件与令牌解耦，变体用属性驱动 | 不引入任何 UI 框架（TDesign/Vant），会直接摧毁现有品牌语言 |

**核心判断：本项目的色相体系是对的，问题在明度阶梯与使用纪律。** 因此 v4 不换色，只重排"哪一阶用在哪里"。

## 五、v4 优化方案

### 5.1 颜色：保留色相，补齐明度阶梯

| 角色 | 现状 | v4 | 对比度（bg / surface） |
|---|---|---|---|
| paper `--ink` | `#1B1712` | 不变 | 14.37 / 15.05 |
| paper `--ink-2` | `#5E5346` | 不变 | 6.04 / 6.66 |
| paper `--ink-3` | `#7C7060` ❌ 3.90 | **`#6B5F4F`** | **5.02 / 5.53** ✅ |
| paper `--accent` | `#B4381F` | **`#A93218`** | **5.36 / 5.86** ✅ |
| ink `--ink-3` | `#8F836E` ⚠ 4.66(surface) | **`#9A8D77`** | 5.84 / **5.33** ✅ |
| 语义色 ok/info/warn/danger | 仅验证了 bg | 逐个在 `--surface` 上复验，不足则提亮 1 阶 | 目标 ≥4.5:1 |

**使用纪律（新增约束）**：

1. `--accent` 只允许出现在"可操作元素"与"当前选中态"，禁止用于纯装饰线。
2. 印章 `.seal` 每屏不超过 2 处；列表项内不再挂印，改用 4rpx 朱砂竖条。
3. 语义色不得作为背景大面积铺色，只做文字/边框/小面积填充。

### 5.2 排版：19 档收敛到 7 档

| 档位 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| display | 72rpx / 1.1 | 600 | 首页刊头（现 84rpx，压缩 14%） |
| h1 | 48rpx / 1.2 | 600 | 详情菜名、档案姓名 |
| h2 | 36rpx / 1.35 | 600 | 区块标题 |
| title | 30rpx / 1.4 | 500 | 卡片标题、列表主文 |
| body | 28rpx / 1.75 | 400 | 正文 |
| meta | 24rpx / 1.5 | 400 | 描述、辅助信息 |
| caption | 22rpx / 1.45 | 400 | 时间戳、角标（下限，不再更小） |

- **删除 18/20rpx**：目前有 6 处 18rpx 与 23 处 20rpx，低于移动端可读下限。
- 竖排 `.vlabel` 仅保留给单字装饰；分区标题改为横排 `caption` + 4rpx 字距。
- 所有数字继续走 `.num`（`tabular-nums`），这条已经做对。

### 5.3 间距与圆角：4pt 网格 + 3 档圆角

- 间距：`8 / 16 / 24 / 32 / 48 / 64`，删除 12rpx（当前 page 左侧有 24/32 两套，统一到 32rpx 外边距、24rpx 卡内边距）。
- 圆角：`12`（小控件/标签）、`20`（卡片/输入）、`28`（面板/大卡）、`999`（仅胶囊标签）。
- 当前 11 种圆角中，16/18/24 三档与 20 视觉差异小于 2px 却制造了"随手写"的观感，全部归并。

### 5.4 动效：从"逐处调参"到"时序编排"

#### 令牌（5 档时长 / 3 条曲线）

| 令牌 | 值 | 语义 |
|---|---|---|
| `--d-micro` | 120ms | 按压、颜色微变、开关 |
| `--d-short` | 200ms | 按钮、标签切换 |
| `--d-medium` | 280ms | 元素位移、让位、展开 |
| `--d-long` | 420ms | 区域变化、轮播、页面淡入 |
| `--d-sweep` | 560ms | 主题扫过（唯一超 500ms 的场景） |

曲线只保留三条：

```
--e-standard:  cubic-bezier(0.2, 0, 0, 1);      /* 位移与展开，收尾干净 */
--e-decelerate: cubic-bezier(0.05, 0.7, 0.1, 1); /* 入场，快进慢出 */
--e-spring:    cubic-bezier(0.2, 1.12, 0.4, 1);  /* 仅小元素回弹，过冲 ≤6% */
```

> 现用的 `cubic-bezier(.34,1.56,.64,1)` 过冲约 16%，与文档自称的"≤8%"不符，且用在 72rpx 的"想吃"按钮上会显得弹跳过度。

#### 场景时序表

| 场景 | 现状 | v4 | 说明 |
|---|---|---|---|
| 卡片入场 | 460ms，8×50ms 错峰 | 320ms，5×40ms | 首屏 520ms 内完成，超过一屏不再错峰 |
| 按压反馈 | 200ms / 过冲 16% | 120ms / 过冲 6% | 按压要"立刻"，不能等 |
| 品类切换 | 300ms padding 过渡 | 180ms 伪元素 `scaleX` | 消除布局重排 |
| tab 书签 | 440ms | 280ms | 位移仅 1/3 屏宽，长尾显拖 |
| 轮播 | 520ms / interval 4200 | 400ms / 5000 | 与图片切换同步，降低"赶"的感觉 |
| 主题扫过 | 1270ms | 620ms（420 扫 + 80 停 + 120 淡出） | 仪式感保留，交互锁定期减半 |
| 页面淡入 | 320ms | 240ms | 与原生转场时长匹配 |
| 分页追加 | 无 | 140ms 淡入 + 8rpx 上移，30ms 错峰 | 新内容"接上"而非"砸下" |

#### 三条硬规则（写进 code review 清单）

1. **同一元素同一时刻只能有一个 `transform` 所有者**：入场动画挂在外层 wrapper，按压/悬停挂内层，或入场结束后再加类。
2. **禁止过渡 `padding / width / height / top / left`**：形变一律用伪元素 `transform: scaleX/Y` 或 `clip-path`。
3. **覆盖层必须吞事件**：任何全屏遮罩在显示期间 `pointer-events: auto`，结束后复位。

### 5.5 布局：三处结构性改造

**① 底部 Dock 合并（解决 P0-4）**

现状是 tab 栏、购物袋、FAB 三个 fixed 层叠。v4 合并为单层 Dock：

```
┌──────────────────────────────────────────┐
│  首页    留言    档案   │  🧺 3   ［去落单］ │  ← 高 112rpx，单层
└──────────────────────────────────────────┘
```

- 高度 112rpx + `env(safe-area-inset-bottom)`，内容区 padding-bottom 统一为 `160rpx + safe-area`。
- 购物袋数量用 Dock 内角标，不再单独浮层；"写菜牌"入口移到首页刊头右侧（与印章同位），不再悬浮。
- 收益：释放约 150rpx 垂直空间，消除 z 序冲突。

**② 首页首屏重排（解决 P1-2）**

- 刊头 84rpx → 72rpx，"今天/吃什么"两行改一行 + 副标题，高度从 210rpx 降到 132rpx。
- 轮播 360rpx → 300rpx，`previous/next-margin` 48rpx → 32rpx。
- 品类条与列表标题合并为一行（标题左、品类右滑），再省 60rpx。
- 净效果：首屏可露出 **1.5 行 → 2.5 行**菜品。

**③ 导航统一（解决 P1-7）**

- 二级页统一使用自定义导航：左返回（88×88rpx 热区）、居中标题、右侧动作位。
- 详情页头图延伸到状态栏下方，返回按钮浮于图上（带 1rpx 描边保证浅色图上可见）。
- 暗色主题下 `frontColor` 统一为白，避免原生导航重着色的一帧闪烁。

### 5.6 组件化与工程治理

| 动作 | 说明 | 收益 |
|---|---|---|
| 拆分样式 | `styles/tokens.wxss`（仅变量）/ `styles/base.wxss`（reset+排版）/ `styles/components.wxss`（组件类） | 页面可按需 `@import`，组件样式隔离问题一次解决 |
| 抽取组件 | `<dish-card>` `<ledger-row>` `<empty-state>` `<bottom-dock>` `<section-head>` | 12 页重复实现收敛到 5 个组件 |
| 统一数据入口 | 页面只调 `db.js`，组件不直接发请求 | 便于加缓存与错误兜底 |
| 请求合并 | `onShow` 的身份/分类/轮播改 `Promise.all` + 5s TTL 缓存 | 首屏云调用 3 次 → 1 轮并发 |
| 列表刷新 | 保留旧列表，用顶部 2rpx 进度条表示加载，不再清空 | 消除搜索时的闪空 |
| 视觉回归 | 扩展 `preview/` 为多页静态基线，接入截图 diff | 重构可验证"没改坏" |

### 5.7 无障碍补充

- 所有可点区域 ≥88rpx（44px）：`.want` 视觉 72rpx + 8rpx 透明外扩；`.search__clear` 视觉 36rpx + 26rpx 外扩热区。
- 图标按钮补 `aria-label`（小程序支持 `aria-label`），如"切换主题""删除菜品"。
- 状态不能只靠颜色：订单状态加文字/符号（已有 `statusHistory`，界面需同步）。
- 支持系统字号放大：卡片标题不使用固定高度，改用 `min-height` + `line-height` 组合。

## 七、风险与"不做什么"

**风险**

1. 令牌收敛会触碰大量样式，必须分支推进 + 截图 diff，否则容易"改好一处、坏三处"。
2. 主题扫过从 1.26s 缩到 620ms 会削弱仪式感；建议用"印章落款"（120ms 缩放淡入）补偿情绪价值。
3. 自定义导航统一涉及 8 个页面，返回手势与页面栈需逐页回归。
4. 小程序不支持 CSS `@property`，颜色仍无法插值，换肤只能继续用遮罩方案——这是平台约束，不是设计妥协。

**明确不做**

- 不引入 TDesign/Vant 等 UI 框架：会覆盖现有品牌语言，收益仅为省几天工时。
- 不做毛玻璃、大面积投影、3D 视差：与"纸/墨"材质逻辑冲突，且是低端机掉帧主因。
- 不做无限滚动 + 虚拟列表：当前每页 20 条、总量有限，复杂度不划算。
- 不为动效而动效：任何无法回答"从哪来、改变了谁、去哪了"的动画一律不加。

---

## 八、一句话总结

**保留"食帖"的骨相，重做它的呼吸。** 风格不需要推翻，需要的是把 21 种时长、19 种字号、11 种圆角收敛成一套可被团队复用的秩序，并让每一个像素都通过对比度与触控的硬门槛。
