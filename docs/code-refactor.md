# 全项目代码重构记录

日期：2026-10-24。范围：12 个页面、公共工具、数据访问层、业务云函数及本地检查脚本。原有页面布局、主题资源、原生微信小程序技术栈和云环境配置保留。

| --- | --- | --- |
| 页面 | `pages/` | 交互、展示数据、调用服务 |

## 关键行为

1. **订单原子提交**：订单与每位厨师的消息在同一事务创建。客户端保存当前点菜单的 `requestId`，同一份点菜单重试不会重复建单。内容变更后生成新标识。旧客户端仍可省略此字段。
2. **状态一致性**：接单、完成、取消、管理员操作使用统一状态转换函数；状态与消息一同提交。`pending → cooking → done`，管理员可从进行中直接完成或取消；`done/canceled` 是终态。
3. **制作记录去重**：订单、厨师、菜品组合生成稳定文档 ID；同一订单已完成菜品不能重新加入。完成凭据保存在订单上，清理制作列表不会丢掉订单完成进度。旧的随机 ID 条目仍参与去重和完成判断。
4. **订单快照**：接单按下单时菜品快照处理，菜品后来删除也能完成已有订单；指定菜品必须确实属于该订单及当前厨师。
5. **菜品服务端派生字段**：服务端计算搜索词、封面、分类名称、厨师署名，管理员修改他人菜品时保留原作者身份。
6. **资料保护**：资料创建与修改放在事务中；数据库读取失败直接上抛，不再误判为“首次使用”而重置角色。旧头像在成功写入之后清理。
7. **编辑器图片生命周期**：已保存图片从草稿移除时不删文件。新上传但未保存的图片在放弃编辑时清理；保存期间离开页面等待保存结果；网络结果不明时保留图片，可能遗留待人工核对的文件，避免破坏已保存菜品。
8. **页面竞态**：编辑表单等分类就绪后回填；加载失败禁止覆盖保存。列表统一丢弃过期分页响应。评论发送防连点，删除按评论 ID 定位，避免新评论插入后删错行。
9. **数据清理**：删除菜品评论、清空本人轮播循环分批处理，修复只清理前 100 条的问题。文件清理等待完成并记录失败，不让清理异常掩盖已成功的数据操作。
10. **客户端初始化**：数据库连接延迟至调用时获取，服务模块可以在 `wx.cloud.init` 之前加载。ISO 时间字符串与数据库 Date 采用相同格式化函数。

## 接口和部署兼容性

- 云函数名仍为 `biz`，原有 19 个 action 名称保留，响应仍为 `{ ok, data }` 或 `{ ok: false, message }`。
- 新增 `messageRead`，客户端不再直接更新消息文档。部署必须先更新整个云函数目录，再发布小程序。
- `orders.completedDishIds` 是可选新增字段，代码兼容缺失字段的旧订单。无需清空集合或强制迁移历史数据。
- 云函数仍使用项目原定的 `wx-server-sdk ~2.6.3`。已检查对应安装版本的事务实现：事务中仅用单文档操作，缺失文档通过 `throwOnNotFound: false` 返回 null，`runTransaction` 返回回调结果并处理冲突重试。
- 事务内不执行文件删除等外部调用。事务方法依据 [CloudBase 事务文档](https://docs.cloudbase.net/database/transaction) 与实际 SDK 源码核对。
- 小程序打包排除测试、脚本、文档、预览及本地工具配置；运行时没有增加第三方前端依赖。
- 历史 UI 迁移脚本保留作记录，本次不重新执行；日常校验使用下列命令。

## 验证

```sh
npm test
npm run check
npm run validate:ui
```

`npm test` 覆盖订单与消息原子写入/回滚、重复提交、多厨师完成、越权、旧记录兼容、终态保护、资料错误保护、服务端派生字段、分类同步、批量清理、分页竞态、图片生命周期、评论防连点和页面卸载。

`npm run check` 检查全部 JS 语法、相对模块引用、JSON、页面注册、WXML 事件处理器和两份分词器一致性。`npm run validate:ui` 检查 WXML/WXSS/组件注册及已有设计约束；修复了 Windows 路径处理、写死 Node 路径和失败时返回成功退出码的问题。ESLint 推荐规则已启用，使用本地独立工具目录中的 ESLint 8.57.1 校验。

内存数据库测试验证应用级事务边界和结果，不模拟真实云端网络、权限规则、索引及 SDK 冲突调度。尚未连接真实云数据库或在微信开发者工具/真机中完成端到端验证。分类重命名与菜品冗余名称同步仍是分步操作，文件存储清理也不是数据库事务的一部分。

部署后的人工联调清单：

- 食客首次进入、浏览、搜索、分类、评论和跨页面返回。
- 厨师新建/编辑菜品、移除旧图后放弃编辑、上传新图后保存。
- 食客同时点两位厨师的菜，两位厨师依次接单并完成，食客订单与消息状态一致。
- 待处理订单取消、制作中拒绝食客取消、管理员取消、终态拒绝重新开启。
- 管理员改角色、改分类、编辑他人菜品；未授权用户不能执行特权写操作。
- 断网重试下单、快速刷新/触底、切换主题、减少动效、离开上传/保存中的页面。
